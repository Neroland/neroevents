# NeroEvents privacy & telemetry disclosure

NeroEvents includes anonymous error reporting so that crashes and bugs caused by the mod
can be found and fixed. It is **on by default** and **opt-out** (see
[How to opt out](#how-to-opt-out)). This page is the full disclosure required by CurseForge's
moderation rules for mods that use an external analytics/error service, and it documents how
the system is designed to comply with the GDPR (EU) and POPIA (South Africa).

> **Note:** error reporting is **active by default** as described on this page, and can be
> switched off at any time with `telemetryEnabled = false` (see
> [How to opt out](#how-to-opt-out)). Any build whose `NeroEventsTelemetry.DSN` field is still the
> placeholder (including the current development builds, forks and source builds) sends
> **nothing**, ever — no report leaves the machine and no network connection is opened,
> regardless of the settings below.

## What is collected (error reporting)

When an error **caused by NeroEvents code** occurs, a report is sent to
[Sentry](https://sentry.io) (hosted in the **EU** — `ingest.de.sentry.io`) containing:

- the stack trace of the error and the error message (scrubbed as described below),
- for an error NeroEvents caught and recovered from, a short fixed label naming the part of the
  mod and the operation involved (for example `menu_open` plus a menu's translation key) — never a
  player name, UUID, position or any text a player typed,
- a short trail of recent, non-identifying mod activity ("breadcrumbs") leading up to the error,
- the NeroEvents version, the loader (NeoForge / Forge / Fabric) and its version, the
  Minecraft version, and whether the game is a client or dedicated server,
- the operating system name/version and Java version,
- the list of **other loaded mods** (their public ids and versions only), so a crash caused by
  a mod conflict can be identified,
- a random event ID generated by Sentry for the individual report,
- a random session ID created fresh at each launch (used only to count crash-free sessions; it is
  not stored on your machine and never links one launch to another),
- timing samples for about 5% of traced mod operations (operation name and duration only).

Before anything is sent, your home-directory path and operating-system account name are replaced
wherever they appear — in error messages, log lines, breadcrumbs and the file names of stack
frames — and absolute file paths of stack frames are removed entirely.

Reports are de-duplicated and hard-capped at 10 events per game session.

## What is NOT collected

- **No IP address** is stored (`sendDefaultPii` is disabled; Sentry discards the sender IP).
- **No username, player UUID, or machine/host name.**
- **No world data, chat, coordinates, inventories, or gameplay analytics** of any kind.
- **No advertising or tracking identifiers** — there is no persistent ID linking reports from
  the same player or machine.
- Errors caused by other mods or by Minecraft itself are filtered out and never sent.

## How to opt out

Set the following in `config/neroevents.properties` (created on first launch):

```properties
telemetryEnabled=false
```

This is a client-local switch (not server-synced) and covers everything error reporting sends.
The change takes effect on the next restart of the game or server; nothing is sent while
disabled, and nothing is ever sent before the config — and therefore your choice — has been
loaded.

## Player data

NeroEvents stores a small amount of player data so that people who take part in events are paid
fairly, exactly once, and can see what they earned. Everything below is kept in the world save,
never sent anywhere, never logged with a player id, and removed by an erasure request.

### What is stored

| Store (world save, overworld) | What it holds | Kept for |
| --- | --- | --- |
| `neroevents:rewards` — reward history | One row per player per event that paid them: player UUID, the event's random instance id and definition id, what they received (credits, XP, item count, reputation changes), their rank and share in that event's split, and the time. A row for an opted-out player has no UUID, rank or share. | **7 days** (`privacyRewardLedgerRetentionDays`), at most `rewardLedgerMaxEntries` rows for the whole server |
| `neroevents:crates` — reward crate | Reward items (item id and count only) and XP a player earned but has not claimed yet, per event. | **14 days** (`privacyRewardCrateRetentionDays`); unclaimed rewards are then forfeited |
| `neroevents:privacy` — opt-out list | The UUIDs of players who opted out of stored reward history. Nothing else. | Until the player opts back in or asks for erasure |
| `neroevents/exports/<uuid>.json` — your export | A copy of the above for one player, written only when that player asks for it. | **7 days** |

No retention setting can exceed `privacyRetentionHardCapDays` (90 days at most; it can only be
lowered). Expired rows, crate entries and export files are removed shortly after the world loads (at
the first scheduler pass) and then every `privacyPurgeIntervalMinutes` (hourly by default). With `rewardLedgerEnabled=false` the reward
history is not kept at all.

NeroEvents also saves two world-data stores that name no player:

- `neroevents:engine` — running events' timers, phase, dimension and anchor, per-event cooldowns,
  operator weight overrides, how many events have resolved, and exclusion zones added by command.
- `neroevents:history` — the last `historyMaxEntries` (200) events as counts and totals only (which
  event, when, how it ended, how many took part, how much it paid in total, the public vote counts),
  plus the world's reward spend for the current day. There is no participant list and no location in
  it. The day is the UTC calendar day of the server clock.

The progression records (`neroevents:first_participation`, `supply_claimed`, `raid_repelled`,
`boss_contributor` and `hook/supply_beacon`) are yes/no player-scope rows in Neroland Core's
progression store, covered by Core's PRIVACY.md and erased through Core's shared erasure hook.

### What is kept in memory only

While an event runs it keeps, by player UUID, who contributed and how much (damage dealt to the
event's creatures, containers opened, objectives captured, waves survived — never who was merely
nearby), and, when the server uses consent votes, which way each voting player voted. Only totals are
ever shown. This is never written to disk, logged, broadcast or sent anywhere, is dropped shortly after
the event ends (`instanceRetainTicks`) or when the server stops, and is removed at once by an erasure
request. If the server restarts during an event, everyone's progress toward its rewards is lost.

NeroEvents also keeps in memory which players are online (to hand over a pending quest reward at
login), a per-player limit on how often an export can be requested, and — for players who opted out —
a temporary reward crate and a "paid this session" marker. All of it is dropped when the server stops.

Some events keep a little more in memory while they run, all of it by player UUID, never saved, never
logged and removed at once by an erasure request: during a **faction war**, which side each player was
on when they first came near it (frozen, so changing faction mid-war changes nothing; dropped when the
war is cleaned up); during a **storm**, whether the storm last told each player they were out in the
open (used only to tell them when that changes; cleared when the storm ends); and which players were
already told this login that a Supply Beacon reward is waiting.

Events are placed by counting how many players are in each area of a dimension; the counts are used
and discarded, never a position.

### The Event Console and the event HUD

The console and the on-screen event messages show world information to everyone (which events are
announced or running, where public ones are, vote counts as numbers) and your own reward crate, reward
history and privacy settings only to you. Nothing they send names or identifies another player: an
event is addressed by an opaque key, tallies are numbers, and the location of a raid or invasion
target is never sent. One exception you choose yourself: a Supply Beacon calls its drop to where you
stand, and that drop is announced to everyone online with its direction and rough distance like any
public event, so using one tells others roughly where you are. The console's buttons run the same
actions as the commands below. Where you put the event messages on your screen is saved only on your
own computer (`config/neroevents-hud.properties`) and never sent to a server.

### Your choices

The same choices are on the Event Console's **Privacy** tab (Export, Opt out / Opt in, and Erase, which
opens the chat with the `/neroland data eraseme` command typed in for you to send).

- `/neroevents privacy optout` — NeroEvents stops storing reward history under your id. You are
  still paid: credits go to your account, items and XP wait in a temporary crate that is cleared when
  the server restarts (claim them with `/neroevents claim` first). Because nothing is stored, a restart
  during an event could pay you twice or not at all for that event. Rows written before you opted out
  keep your id until they expire or you ask for erasure. Opting out again changes nothing.
- `/neroevents privacy optin` — stored reward history resumes; rows written while you were opted out
  stay anonymous: they hold no player id, no rank and no share, only what the event paid.
- `/neroevents privacy status` — what is kept about you and for how long.
- `/neroevents privacy export` — everything NeroEvents holds about you, as one JSON file in the world
  folder (ask the server operator for it). It never contains another player's data.
- `/neroland data eraseme` (or an operator's `/neroland data erase <uuid>`, or Core's inactivity
  sweep) — removes your reward history, your crate, your opt-out row, your export file and everything
  held in memory about you, and refreshes the stores' backups so nothing comes back from them.
  **Erasure forfeits unclaimed reward crate items; claim them first with /neroevents claim.**

This version of NeroEvents registers no NeroLink companion-app module: it sends no event data to the
app and no notification to anyone. A server operator can already switch off every future event
notification and stored alert with `pushNotificationsEnabled=false`. When the module ships, this
document will describe exactly what it sends before it is enabled.

Credits are paid through NeroEconomy when it is installed; NeroEconomy keeps its own ledger and
documents it in its own PRIVACY.md. Reputation changes go through NeroFactions when it is installed:
during a faction war NeroEvents reads which faction players near an objective belong to, and at the end
it asks NeroFactions to adjust the reputation of the players who took part (capped by
`rewardReputationMaxDeltaPerEvent`). NeroEvents stores neither; NeroFactions' PRIVACY.md covers what it
keeps. A market shock sends NeroEconomy a price request that names no player.

## Legal basis and your rights (GDPR / POPIA)

Error reports are processed on the basis of **legitimate interest** (GDPR Art. 6(1)(f); POPIA
s11(1)(f)): keeping the mod functional and crash-free, using the minimum data necessary. They
are engineered to contain no directly identifying personal information, are stored in the EU,
and are retained only for Sentry's standard retention period before automatic deletion.

The player data described under [Player data](#player-data) is kept by the server you play on, not
sent to the NeroEvents developers. It is processed so the server can run its events fairly (pay each
participant once, let them see and claim what they earned), on the same legitimate-interest basis,
with the shortest retention that does the job. The server operator is responsible for it; the
commands above let you see it, export it, limit it and erase it yourself.

To exercise any data-subject right (access, deletion, objection), contact
**[info@neroland.co.za](mailto:info@neroland.co.za)** — for a crash report, include the
approximate date/time of the crash so the matching event can be located and removed. Sentry
acts as a data processor for error reports; see
the [Sentry privacy policy](https://sentry.io/privacy/) and
[data processing addendum](https://sentry.io/legal/dpa/).

You also have the right to lodge a complaint with a data-protection supervisory authority: in South
Africa the Information Regulator ([inforegulator.org.za](https://inforegulator.org.za)), and
elsewhere the data protection authority where you live (for the EU, your member state's authority).

## Changes to this policy

Whenever a version of NeroEvents starts storing new player-attributable data, this page is updated
**before** that version is released, the change is called out in the changelog, and the data is
registered with Neroland Core's shared per-player data-erasure hook so a single erasure request
purges it alongside every other Neroland mod. Likewise, if a future version ever collects additional
telemetry, this page will be updated before release and the same opt-out
(`telemetryEnabled = false`) will continue to cover everything error reporting sends.
